`//synthetic:m4_prefix_parity` inside the insula.

## Build recipe

`native/m4/m4.bzl` mirrors Spack's out-of-tree Autotools flow:

```text
mkdir -p <src>/spack-build
cd <src>/spack-build
PATH=<diffutils-prefix>/bin:$PATH
CPPFLAGS=-I<libsigsegv-prefix>/include
LDFLAGS=-L<libsigsegv-prefix>/lib -Wl,-rpath,<libsigsegv-prefix>/lib
LIBS=-lsigsegv
../configure --prefix=<prefix> \
  --enable-c++ --with-libsigsegv-prefix=<libsigsegv-prefix>
make V=1
make install
find <prefix> -type f -name '*.la' -delete
```

The repository rule fetches the same upstream tarball by SHA256 and refuses to
run unless the hermetic insula has set `VASO_IN_INSULA=1`. Its dependencies are
not discovered from the host: `diffutils_prefix_file` and
`libsigsegv_prefix_file` are mandatory Bazel labels, read by the repository
rule, validated by the shell build, and passed through the Autotools build
channel. The corresponding mechanism verifier is
`//tools:hermetic_native_deps_guard_test`, which reports:

```text
native/m4/m4.bzl: autotools: DIFFUTILS_PREFIX, LIBSIGSEGV_PREFIX
```

## Prefix and behavior gate target

`//synthetic:m4_prefix_parity` compares the native prefix against the hermetic
Spack reference. `m4` emits no public C library ABI, so the gate covers:

- layout parity for `bin/m4` plus selected info/man data;
- exact SHA256 parity for `share/info/m4.info`, `m4.info-1`, `m4.info-2`, and
  `share/man/man1/m4.1`;
- executable dynamic dependency parity for `bin/m4`;
- matching `m4 --version` output;
- matching macro expansion output for a deterministic input.

The smoke target prints:

```text

```
