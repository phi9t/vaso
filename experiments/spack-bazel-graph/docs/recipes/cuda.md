## Hermetic Spack Evidence

- Source of truth: Bazel-vendored Spack `@spack_dist//:spack`, pinned to
  upstream Spack `v1.2.2`.
- Recipe path in the hermetic Spack cache:
  `/vaso/cache/spack/user/package_repos/.../repos/spack_repo/builtin/packages/cuda/package.py`.
- The recipe is `Cuda(Package)`, a `generic` Spack package around NVIDIA's
  binary local installer, not a source build.
- Linux x86_64 installer for `12.9.1`:
  `cuda_12.9.1_575.57.08_linux.run`
  with SHA256
  `0f6d806ddd87230d2adbe8a6006a9d20144fdbda9de2d6acc677daa5d036417a`.

## Recipe Contract

The Spack recipe declares:

- variants: `dev=false`, `allow-unsupported-compilers=false`
- build deps: `coreutils`, `gzip`, and `libxml2@:2.13`
- installer environment:
  - `LIBXML2HOME=<libxml2 prefix>`
  - `LD_LIBRARY_PATH+=<libxml2 prefix>/lib`
- install command for `@10.1:`:
  - run the installer via `sh`
  - `--silent`
  - `--override`
  - `--toolkit`
  - `--tmpdir=<stage>/tmp`
  - `--installpath=<prefix>`
- dependent/run environment:
  - `CUDA_HOME=<prefix>`
  - `NVHPC_CUDA_HOME=<prefix>`
  - `CUDAHOSTCXX=<dependent C++ compiler>` when requested

## Native Boundary Decision

CUDA is an SDK/rootfs boundary in this experiment. The native provider does not
download or rebuild CUDA from source. Instead, `native/cuda/cuda.bzl` exposes the
SDK already present in the hermetic insula rootfs after validating:

- the repository rule is evaluated inside the insula (`VASO_IN_INSULA=1`);
- `VASO_CUDA_HOME/bin/nvcc` exists;
- `VASO_ROOTFS_BUNDLE_MANIFEST` points at the rootfs provenance manifest;
- the rootfs manifest's `base_image` contains `cuda:12.9.1`;
- `nvcc --version` reports exactly `12.9.86`, the compiler build shipped by
  `nvidia/cuda:12.9.1-cudnn-devel-ubuntu24.04`;
- the Spack-declared installer build dependencies arrive as Bazel-native
  prefixes: `COREUTILS_PREFIX`, `GZIP_PREFIX`, and `LIBXML2_PREFIX`.

This is covered by the mechanism-specific verifier:

```text
//tools:hermetic_native_deps_guard_test
native/cuda/cuda.bzl: sdk-boundary: COREUTILS_PREFIX, GZIP_PREFIX, LIBXML2_PREFIX
```

## Current Status

CUDA is now flipped in `native_overrides.json` as:

```json
"cuda": "@cuda_native//:lib"
```

The verified CUDA 12.9.1 insula estate is:

```text
VASO_ESTATE_ROOT=$VASO_ESTATE_ROOT
base_image = nvidia/cuda:12.9.1-cudnn-devel-ubuntu24.04
ubuntu_version = 24.04
nvcc_version = 12.9.86
```

The native boundary manifest emitted by `@cuda_native` records:

```text
mechanism = sdk-boundary
expected_cuda_version = 12.9.1
expected_nvcc_version = 12.9.86
actual_nvcc_version = 12.9.86
installer_build_deps = coreutils, gzip, libxml2
```

The provider flip was verified without a Spack CUDA install:

```text
VASO_ESTATE_ROOT=$VASO_ESTATE_ROOT
VASO_NATIVE=1
SPACK_ROOT_PKG='cuda@12.9.1'
VASO_SPACK_INSTALL=0
VASO_EXTRA_TEST_TARGETS='//synthetic:use_cuda_boundary'
./run.sh
```

The run used Bazel's vendored Spack path
`../+spack_toolchain+spack_dist/spack`, kept all work inside the bwrap insula,
and passed `//tools:hermetic_spack_guard_test`,
`//tools:hermetic_native_deps_guard_test`, `//tools:spack_to_bazel_unit_test`,
and `//synthetic:use_cuda_boundary`.

The CUDA lock entry generated by that no-install path is native and intentionally
has no Spack prefix:

```json

  "build": "native",
  "native_prefix": "@cuda_native//:lib",

```
