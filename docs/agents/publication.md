# Publication

Official GitHub publication uses a sanitized snapshot, never source branch
history.

## Privacy contract

Remove our personal and machine identifiers from published source and artifact
payloads: host account names, personal email addresses, hostnames, host paths,
IP addresses, MAC addresses, GPU UUIDs, and private infrastructure references.
Cover filenames, symlink targets, metadata, logs, and identifiers embedded in
our binaries, as well as ordinary text. Keep credentials and scrub rules outside
Git and publication payloads.

Absolute paths inside the insula rootfs are allowed. A path such as `/vaso`,
`/opt/vaso/python`, or `/workspace/repo` describes the runtime namespace. A host
identifier remains private even if copied into that namespace. Preserve
vendor-supplied CUDA, cuDNN, and TensorRT binaries and their upstream build
metadata; remove our identifiers without modifying vendor bytes.

The snapshot publisher combines external replacement rules with host-identity
checks. Its checks cover known host tokens and specific identifier patterns;
they are not a general detector for every possible personal identifier. Supply
identifiers from other build hosts through external rules or `--host-token`.
Review new payload formats and metadata before relying on existing scans.

## Flow

1. Start from the private source revision and the public base revision.
2. Create a fresh worktree from the public base.
3. Replace the worktree contents with `git archive` output from the source
   revision. This carries tracked files only, not history or untracked outputs.
4. Exclude agent and tracker state: `.scratch/`, `.claude/`, `.trae/`, and
   `.worktrees/`. Apply committed public-snapshot excludes from
   `tools/publish/publication-excludes.txt`, plus any path excludes from the
   external rules file.
   Gate evidence lives on the estate and is never published; the tracked pointer
   is `.scratch/production-build/evidence-archive.md`.
5. Apply the publication overlay in the temporary worktree. The overlay removes
   BUILD targets, exported file entries, and documentation/allowlist lines that
   reference committed public-snapshot excludes.
6. Apply scrub rules to text file contents and path names.
7. Run the committed post-scrub regeneration commands in
   `tools/publish/publication-regenerate.txt`. These commands update derived
   pins in the temporary public tree only.
8. Re-scan the scrubbed tree. If any active rule still matches, stop closed.
   The rescan also stops closed on machine-identifying residue the rules
   missed: host volume paths (`/dataNN/`), `/Users/` paths, GPU UUIDs, MAC
   addresses, and the running host's user name, hostname and IP addresses
   (plus any `--host-token`). Absolute paths inside the insula rootfs are allowed, including `/usr`,
   `/opt`, `/home`, `/workspace/repo`, and `/vaso`. Scrub our host identities
   and host paths; preserve vendor binaries and their upstream build metadata.
   Inside insula, pass known host identifiers explicitly with `--host-token`;
   namespace account and host names are not host identity discoveries.
9. Run the configured verify command in the scrubbed worktree. The default is
   `tools/agents/standing-verify.sh --agent publish-snapshot`.
10. Stage and re-scan the files produced by verification, excluding ignored
    caches. Refuse private tracker state or identifying data generated by verification.
11. Create one clean snapshot commit with the publishing identity.
12. Push only a `publish/<name>` branch for human pull request review.

When the user explicitly authorizes direct updates to release branches, publish
the verified snapshot commits to those branches. Keep each commit based on its
public branch history. For `main` and `ultron/mainline`, verify that both commits
have the same reviewed tree, use an atomic fast-forward push, and check the
remote tips afterward. The helper's protected-branch restriction still applies;
direct branch updates are a separate Git operation.

GitHub receives only the one snapshot commit on top of the public base. It must
never receive private source history, private trailers, local worktree state, or
the scrub rules file.

## Tool

Use `tools/publish/publish_snapshot.py`:

```sh
VASO_ESTATE_ROOT=/path/to/estate \
  tools/publish/publish_snapshot.py \
  --source HEAD \
  --base origin/ultron/mainline \
  --branch publish/<name> \
  --dry-run
```

Rules default to `$VASO_ESTATE_ROOT/publish/sanitize-rules.json` and must live
outside the repository. The file supports legacy two-string regex replacement
pairs and object rules:

```json
[
  ["regex pattern", "replacement"],
  {"literal": "literal text", "replace": "replacement"},
  {"regex": "regex pattern", "replace": "replacement"},
  {"regex": "regex pattern", "replace": "replacement", "include_globs": ["path/glob/**"]},
  {"literal": "literal text", "replace": "replacement", "exclude_globs": ["path/glob/**"]},
  {"exclude": "path/glob/**"}
]
```

`include_globs` limits a replacement rule to matching repository-relative paths.
`exclude_globs` skips matching repository-relative paths. Scoped rules are also
scoped during the fail-closed rescan, so only use scopes when the rule is meant
to sanitize a declared file family rather than the whole tree.

Run `--dry-run` first and record only the summary: file count, hit counts by
rule index, rescan status, and verify result. Do not record rule terms.

Use `--push` only after the dry-run and verify results are reviewed. The tool
refuses protected branches, refuses non-`publish/` branches for push, and never
force-pushes.

## Guard

The rules file is external state. To check that it or its terms were not added
to the tracked tree, run:

```sh
tools/publish/publish_snapshot.py \
  --rules /path/to/sanitize-rules.json \
  --check-rules-not-tracked
```

Guard diagnostics identify rule indexes and paths only. They must not print
rule terms.

## Evidence and retained history

Keep a publication receipt under `$VASO_ESTATE_ROOT/publish/`, outside the
published tree. Record the source revision, public base revisions, resulting
snapshot commits and tree identities, file count, rule hit counts by index,
pre- and post-verification scan results, rules-guard result, verification
commands and outcomes, and verified remote tips. Record artifact checksums and
OCI digests when artifacts are part of the publication. Keep rule terms, tokens,
and raw identifying diagnostics out of receipts and public logs.

Before replacing or rewriting local history, retain a private backup of the
original commits and required artifacts. Keep backup refs local; push explicit
publication refs rather than `--all` or `--mirror`. Synchronize local branch
refs only after confirming the remote result and preserving concurrent work.

Publishing a clean snapshot does not remove older Git objects, pull request
refs, caches, or previously uploaded package versions. A history rewrite and
force-push alone cannot establish that GitHub has purged those copies. Older
GHCR versions remain private under the current retention decision; deletion or
service-side purging is separate work and must not be reported as completed
without evidence.

## Artifact store

Release wheels and insula rootfs bundles are mirrored as private OCI artifacts
under `ghcr.io/phi9t` with `oras`. Install the pinned CLI first:

```sh
export VASO_ESTATE_ROOT=$VASO_ESTATE_ROOT/.vaso-estate
tools/publish/install_oras.sh
```

Keep wheels and rootfs bundle blobs in the artifact store rather than Git.
Prepare and inspect sanitized artifact copies before uploading; the artifact
store's checksum and visibility checks do not scrub their contents. Inspect
unpacked wheels and rootfs payloads, including build metadata, archive member
names, logs, and our embedded binary strings. Preserve the actual build
provenance in private evidence. Sanitized derivatives receive new checksums;
regenerate dependent manifests and verify restoration and runtime behavior
against those identities. A clean source scan does not establish artifact
privacy, and a private package is not evidence of sanitization.

Push a release directory:

```sh
export VASO_ESTATE_ROOT=$VASO_ESTATE_ROOT/.vaso-estate
export GHCR_TOKEN=...
tools/publish/artifact_store.py push-release \
  --release-dir "$VASO_ESTATE_ROOT/releases/torch/cu129/<version>" \
  --line cu129 \
  --profile torch
```

Push a rootfs bundle:

```sh
export VASO_ESTATE_ROOT=$VASO_ESTATE_ROOT/.vaso-estate
export GHCR_TOKEN=...
tools/publish/artifact_store.py push-rootfs --line cu129
```

Rootfs bundles paired with the CPython 3.13 wheels must contain the qualified
Python 3.13.13 runtime. Copy its native install prefix into the new rootfs at
`/opt/vaso/python`. Inside insula, mount that copy writable and the original
provider output base read-only at `/vaso-bazel-ob`, then run:

```sh
python3 insula/rootfs/release_python.py \
  --qualified-prefix /vaso-bazel-ob/external/+python_native+python_313_native/prefix
```

This copies the interpreter's native shared-library closure and makes its ELF
search paths relative to the bundled prefix. It writes
`/opt/vaso/release-python.json` with installed file hashes. Record that manifest's
hash and Python version in the bundle manifest's `release_python` entry.
Validate native module imports and ELF dependency resolution in a new insula
with the provider output base absent before publishing. Vendor CUDA binaries
retain their bytes. Native build plans and their selected toolchains are
separate from this deployment runtime addition.

An already prepared archive can be published with
`push-rootfs --line cu129 --bundle /path/to/rootfs-cu129-<sha256>.tar.zst`.
The archive's sidecar and `rootfs-bundle.json` must sit beside it. Verify a new
estate by pulling the published digests, unpacking the rootfs bundles, and
running the wheel releases through `foundry/insula.sh --release` without
interpreter or build-prefix overrides.

Pull and verify by tag or digest:

```sh
tools/publish/artifact_store.py pull \
  --artifact release \
  --profile torch \
  --line cu129 \
  --digest sha256:<manifest-digest> \
  --target-dir "$VASO_ESTATE_ROOT/publish/restore/release"

tools/publish/artifact_store.py pull \
  --artifact rootfs \
  --line cu129 \
  --digest sha256:<manifest-digest> \
  --target-dir "$VASO_ESTATE_ROOT/publish/restore/rootfs"
```

For dry runs and tests, pass `--dry-run --registry
$VASO_ESTATE_ROOT/agents/<agent>/oci`; this uses an ORAS OCI layout directory
and does not contact the network. Tokens come only from `GHCR_TOKEN` or
`$VASO_ESTATE_ROOT/publish/ghcr-token`, and the token file must be mode `600`.
After a real GHCR push with a token, the tool checks the GitHub package API and
fails if the package visibility is not `private`.
